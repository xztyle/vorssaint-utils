# Aster clipboard library

Aster keeps a local library of copied text, formatting, images and file references.
The library slides up from the very bottom of the active display, across its full
width and above the Dock. It contains a horizontal row of visual cards and named,
colored collections. Drag its invisible top edge to change its height; shorter
drawers use compact cards. The height is saved locally and clamped to the current
display. It has no floating gap, title bar, visible resize handles or window
dragging. Reduced motion removes the slide. The notch can open the same drawer
through its expand action; normal history opens always use the drawer.

## Use

- Open Clipboard with its configured shortcut. Search has focus first.
- Return from Search selects a result. Return on a selected result pastes it.
  Without Accessibility, it copies and displays the permission requirement.
- Shift-Return pastes a text item without formatting. Command-C copies only.
- Arrow keys move through cards. Command-Up/Down selects the first/last result.
  Shift-Arrows extend selection. Command-click and Shift-click also select several.
- Command-1 through Command-9 acts on the numbered cards currently in view.
- Space opens a preview attached above the selected card. The timeline keeps its
  width and position. Command-E edits a new copy; the original is retained.
  Command-R edits the searchable title.
- Tab and Shift-Tab move between Search, results and collections. Command-F returns
  to Search. Escape closes the preview, clears selection/query, then closes the drawer.
- Drag a card onto a collection, or use its context menu. Collection menus rename,
  recolor, move and remove boards. Removing a board preserves its clips in history.
- Drag a file card's file icon into another app to transfer every file in that
  clip. If any referenced file is unavailable, the group is not dragged.
- Search accepts ordinary substring terms plus `type:text`, `type:image`,
  `type:files`, `app:safari`, `after:2026-01-01`, and `before:2026-12-31`.
  Image text is indexed after local OCR completes. No network preview is fetched.

With Liquid Glass enabled on macOS 26, the drawer uses glass for its navigation
and action bars. Content cards stay solid for readable previews. Reduce
Transparency and Increase Contrast use solid surfaces; Reduce Motion removes
the drawer slide.

## Storage and privacy

The SQLite library uses transactions, FULL synchronization, a local substring
index, owner-only files, and external byte-preserved rich-content payloads. A
successful save is shown separately from a pending or failed save. There is no
whole-library JSON size budget. Capture still has explicit per-item limits:
1,000,000 text characters, 16 MiB PNG, 64 MiB raw/rich content, and 100 file
references. Unsupported or excessive supported payloads produce a visible error.
File references do not copy the underlying files; unavailable files remain visible.

History defaults to Forever, including upgrades from the old count-limited store.
Settings can apply 1, 7, 30 or 365 days after showing the affected count and stored
content size. Collection items do not expire. Recopying updates the latest date
and copy count while preserving the first-copy date.

Secret-marked, transient and autogenerated clipboard content is rejected before
payload reading. Excluded-app tracking covers the entire polling interval.
Uncertain source attribution is shown as Unknown app. Capture can be paused.
The 0.8-second poll cannot recover copies overwritten before a poll observes them.

Export creates a `.asterclipboard` directory package containing a consistent
SQLite online snapshot, referenced image/rich payloads, a versioned manifest and
SHA-256 checksums. It contains private material. Restore checks the entire package
before asking to merge or replace. Merge preserves an existing UUID's local copy.
Three local recovery packages are retained around restores. Settings backup carries
retention configuration, never library content. There is no iCloud sync.

Known old Aster/Vorssaint JSON history is staged and imported without editing its
source. Missing images remain explicit unavailable entries. Invalid/oversized
legacy input stops migration and displays an error. Stable IDs and completion
markers make restart safe. Original source files and migration staging remain as
recovery copies; ordinary deletion is not a claim of forensic secure erasure.

## Safe visual fixture

The executable supports an explicit disposable profile:

```
./build/Aster --clipboard-fixture=/absolute/empty/test-directory
```

Add `--clipboard-fixture-count=50000` for a generated large library. The fixture
runs only the real clipboard drawer. It does not start the app delegate, clipboard
capture, utility services, personal-history migration or personal-defaults import.
It contains generated text, a link, a color, a local drawing, formatted text,
a generated file and an unavailable file. Copy actions use a private named pasteboard in this mode. No target app is remembered, no global paste is sent, and no Accessibility request runs. It is for root-coordinated UI acceptance.

`ui-state.json` in the disposable profile records the drawer geometry, display
geometry, layer level, visibility, query/count and the private fixture pasteboard
type names after presentation, dismissal and preview changes. It never reads the
general pasteboard. The drawer slides content inside clipped bounds so it cannot
spill onto a second display arranged below the active one.

## Paste focus timing

After selecting a history item, the drawer now gives the previous app up to
0.8 seconds to regain focus instead of checking only once after 0.12 seconds.
It sends Command-V only when that exact app is foreground. If focus never
returns or the app closes, it sends no paste keystroke and gives feedback.
The existing Accessibility permission gate remains in place.

The production paste methods run against test doubles for immediate focus,
slower activation, missing focus, a terminated app and missing permission.
The clipboard suite passed 693 checks. The optimized bundle and packaged
selftest passed. A real paste into another app is still a separate Mac UI gate.

## Same-time history order

Two copies can have the same recorded time. The database previously skipped a
position update when their content was unchanged, so moving those cards could
restore the old order after a restart. It now saves position changes in the same
transaction as content changes. A reopened database retains the new order,
including when older copies acquire an equal timestamp. The focused clipboard
suite passes 695 checks. This is a storage check; actual drawer navigation and
paste into another app still need live acceptance.

## Backup merge order

The merge path previously rebuilt entries from a dictionary. When multiple
copies shared a timestamp, that lost their saved card order. It now keeps the
current library order first, appends only new backup entries in their saved
order, and sorts by copy time with that order as the tie breaker. A disposable
merge with four equal-time entries and one newer entry verifies both existing
edit precedence and the order after reopening the database. The focused
clipboard suite passed 698 checks, and the optimized signed build passed.
This is backup storage evidence; the live drawer and cross-app paste gates
above remain open.
