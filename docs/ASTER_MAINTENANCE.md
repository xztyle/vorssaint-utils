# Maintaining Aster

Aster is the personal `xztyle/vorssaint-utils` fork. The `origin` remote is the
fork; `upstream` is `vorssaint/vorssaint-utils`. The inherited source directory
and copyright headers are retained for attribution and manageable upstream merges.

## Identity

- Display and executable name: Aster (AsterDeveloper for development builds).
- Bundle ID: `io.github.xztyle.Aster`; development: `io.github.xztyle.Aster.dev`.
- Protected helpers must have the same signing certificate and their exact own ID.
  Missing certificates fail closed. `Tests/AppIdentityTests.sh` exercises real
  macOS signature acceptance/rejection, including modified binaries.
- `Tools/setup-signing.sh` creates the local `Aster Local Signing` certificate.
  Keep it for future builds so macOS permission grants remain valid. Never commit
  its private key. This local certificate is not Apple Developer ID notarization.
- Original Aster petal artwork is generated by `Tools/MakeIcon.swift`; the adaptive
  source uses `Resources/Brand/AppIcon.icon/Assets/aster-brandmark.svg`.

## Updates and services

This version is built from reviewed source. Automatic binary updates are disabled;
manual Check for Updates opens the fork repository. It cannot install upstream
Vorssaint binaries over Aster. The inherited release workflow is restricted to the
upstream repository and does not publish Aster. A separate reviewed signing and
notarization setup is required before publishing releases.

Upstream feedback submission and hosted screenshot/recording uploads are disabled.
Local captures and exports do not depend on a cloud service. Aster has no hosted
endpoint; do not repoint it to an invented URL or silently send user data upstream.
Upstream source and donation links remain available as explicitly named attribution.

## Integrating upstream changes

1. Fetch `upstream` and review its changes relative to the last integrated commit.
2. Merge the chosen upstream revision into a review branch; keep Aster's identity,
   signing requirements, update policy, storage namespace and five feature areas.
3. Resolve conflicts deliberately. Do not copy an upstream app bundle over Aster.
4. Run the optimized build, selftest, relevant feature tests, all tests before
   integration, and actual Mac behavior checks for changed UI or hardware paths.
5. Merge the verified result to `main` and push to `origin`.

The owner authorized the initial feature branches and their merges. Periodic
upstream merges are deliberate maintenance work, not an unattended binary updater.
See [the product contract](ASTER_PRODUCT.md) for completion requirements.
